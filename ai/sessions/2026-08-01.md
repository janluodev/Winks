# 2026-08-01 — Supabase 暂停诊断与 Keepalive 加固

## 1. 现象

- Supabase Winks 免费层项目再次显示 paused。
- GitHub Actions Keepalive run `30637414809` 于 2026-07-31 失败。

## 2. 根因

- 失败日志是 `Could not resolve host: ukwuafaoifwdkpvedvih.supabase.co`，三次 curl 均停在 DNS 层，尚未进入鉴权或 PostgREST。
- 旧调度 `0 12 */3 * *` 每 3 天只产生一次用户数据库查询；Supabase 当前公开口径是过去一周通常需要每天数次用户数据库请求。
- 旧任务位于整点，GitHub Actions 官方说明整点高峰更容易发生延迟或任务丢弃。

## 3. 修复

- 调度改为 `23 1,9,17 * * *`，每天三次并避开整点。
- 保留对 `links` 的只读查询，不写入业务数据。
- 增加 concurrency、3 分钟 job 超时、5 次全错误重试、no-cache 请求头和 JSON 数组校验。
- 网络不可达时输出明确的 Dashboard Resume 指引。
- README、current iteration 与 `.cloud.md` 同步更新。

## 4. 验收

- Supabase Management API：`ACTIVE_HEALTHY`。
- DNS：项目域名 A 记录恢复。
- PostgREST：匿名 `links?select=id&limit=1` 返回 `HTTP 200` 和一条记录。
- 待远端提交后手动触发新版 workflow，验证 GitHub Runner 路径。

## 5. 剩余风险

- 免费层 Keepalive 是尽力而为，不构成可用性 SLA；唯一官方免暂停方案是付费计划。
